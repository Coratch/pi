# Pi Agent 能力因素地图

影响 coding agent 能力的因素框架(实验设计的理论基础)。落地到 pi 具体变量的清单见 [ablation-variables.md](ablation-variables.md)。

## 七层框架

### 1. 模型层(能力上限)

| 因素 | 影响 | pi 对应 |
|---|---|---|
| 基座模型本身(代码/推理能力) | ★★★★★ 决定上限,其他层都只能逼近它 | provider/model 选择(可消融) |
| 推理档位(thinking/effort) | ★★★★ 高思考对难题提升显著 | thinkingLevel 7 档(可消融) |
| 输出预算 | ★★ 截断会毁掉工具调用 | maxTokens(主循环未显式传) |

### 2. 提示词层(能力引导)

| 因素 | 影响 | pi 对应 |
|---|---|---|
| 工具使用指南(edit 规则、工具选择建议) | ★★★★ 直接影响编辑精确性和工具选择 | promptGuidelines 段(可消融) |
| 项目上下文(CLAUDE.md 规范注入) | ★★★ 决定 agent 是否遵守项目约定 | project_context 段(可消融) |
| 领域文档/示例 | ★★ 对特定技术栈任务有效 | 文档指针、few-shot(可消融) |
| 任务描述质量(用户 prompt) | ★★★ 任务不清晰时再强的 agent 也跑偏 | eval prompt 设计 |

### 3. 上下文层(能力持续性)

| 因素 | 影响 | pi 对应 |
|---|---|---|
| 压缩策略(LLM 摘要 vs 截断) | ★★★★ 长任务关键:摘要丢关键决策 → agent 重蹈覆辙 | compaction 算法(改代码级) |
| 压缩触发阈值 | ★★ 过早伤记忆、过晚爆窗口 | reserveTokens(配置级) |
| 工具结果截断 | ★★★ 基于残缺信息决策 | 50KB/2000 行(改代码级) |
| 历史保留策略(全量 vs 滑动窗口) | ★★ | 全量保留(改代码级) |

### 4. 工具层(能力媒介)

| 因素 | 影响 | pi 对应 |
|---|---|---|
| 工具集构成(编辑 + 检索 + 执行) | ★★★★ 缺检索工具时大仓库任务退化严重 | 7 内置工具(配置级) |
| 工具描述与 schema 质量 | ★★★ 模型"看菜下单",描述含糊则调用错 | ToolDefinition(改代码级) |
| 工具粒度(大而全 vs 小而专) | ★★ | 内置工具设计 |

### 5. Agent Loop 层(能力执行)

| 因素 | 影响 | pi 对应 |
|---|---|---|
| **环境反馈闭环(agent 能否跑测试验证)** | ★★★★★ 业界共识最强的非模型因素:能跑测试的 agent 在 SWE-bench 上比不能跑的高 10–20pp | 评估环境设计(runner 层) |
| 循环终止条件(轮数上限) | ★★ 无限循环烧钱;过早终止半途而废 | 无上限(evals 已加 maxTurns) |
| 错误处理(重试策略、错误反馈格式) | ★★★ 错误信息可操作性决定恢复成功率 | 无工具级重试;模型层重试可配 |
| 并行 vs 串行工具调用 | ★★ | toolExecution(已透传) |
| 截断保护(length-stop 处理) | ★★ | 有(改代码级) |

### 6. 环境层(能力边界)

- 沙箱隔离质量(权限边界)
- 文件系统/网络访问范围
- 工作目录状态的可观测性

### 7. 记忆层(长期任务)

- 会话内状态跟踪(todo/计划机制)
- 跨会话记忆——pi 目前没有,长任务靠 compaction 摘要兜底

## 实验变量 × 给定 划分

- **实验变量(高杠杆 × 可操作)**:thinking 档位、工具集、提示词组件(edit guidelines/文档/项目上下文)、重试策略、压缩参数、**环境反馈(跑测试 vs 不跑测试,runner 层消融,零 API 成本但结论价值极高)**
- **改代码级(高杠杆 × 需工程)**:压缩算法质量、工具描述、每轮输出预算
- **给定**:基座模型(deepseek-v4-pro)、公司网络环境

## 消融顺序原则

按"影响强度 × 实验成本"排序:环境反馈 > 工具集 > edit guidelines > thinking 档位 > 重试/压缩参数。
压缩/上下文类变量在短任务(Polyglot)上不触发,归慢环或长任务专用。
